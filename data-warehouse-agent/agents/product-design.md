# 数仓与数据应用 Agent 产品设计

## 1. 目标与范围

为数仓与数据应用产品团队提供六类专业 Agent，覆盖“需求进入、规则治理、研发设计、运行保障、问题定位、版本上线回写”的完整闭环。

适用数据域：销售、物流、售后、库存、采购、跨境、财务净利及老板报表。

不在本期范围：直接修改生产数据、直接发布生产任务、替代数仓开发/财务对业务口径的最终确认。

## 2. 总体架构

```text
产品需求 / Excel / DDL / 业务确认 / DAS 与 ETL 代码 / 调度运行记录
                              │
                              ▼
                统一资产库（Git + 文档 + 来源登记）
                              │
      ┌───────────────┬───────┼───────────────┬───────────────┐
      ▼               ▼       ▼               ▼               ▼
文档版本管理     口径影响分析  数据研发设计   质量调度运营   排查应用诊断
      │               │       │               │               │
      └───────────────┴───────┴───────┬───────┴───────────────┘
                                      ▼
                         文档、设计、核查、证据与待确认项闭环
```

统一资产库是唯一事实入口，至少包含：表资产、字段映射、指标规则、版本记录、来源证据、调度规则、代码基线、血缘、待确认项及核查结果。

## 3. 六类 Agent

### A1. 文档版本管理 Agent

**定位**：管理“当前什么规则生效、从哪里来的、何时变更”。

| 项目 | 设计 |
|---|---|
| 典型请求 | 解析新 Excel；更新指标文档；对比两个版本；登记 DDL；关闭已确认问题 |
| 输入 | Excel/Markdown/图片/DDL、产品确认、代码基线、资产 ID |
| 输出 | 版本差异、资产草稿、来源登记、变更日志、待确认清单 |
| 关键规则 | 忽略隐藏 Sheet；忽略删除线内容；保留合并单元格语义；历史版本仅追溯不覆盖 |
| 写权限 | Git 文档仓库中的草稿、版本与来源登记 |
| 发布门禁 | 业务口径须产品确认；实现映射须数仓开发确认 |

### A2. 指标口径与影响分析 Agent

**定位**：在需求评审阶段回答“这个指标怎么计算、改动会影响什么”。

| 项目 | 设计 |
|---|---|
| 典型请求 | 新增指标；调整成本口径；变更回刷窗口；判断字段是否可下线 |
| 输入 | 指标需求、现行资产、血缘、代码/SQL 证据、目标版本 |
| 输出 | 标准口径、冲突项、上游/下游影响清单、验收标准、待确认项 |
| 核心检查 | 粒度、主键、日期口径、维度依赖、金额正负号、税额、回刷与历史影响 |
| 写权限 | 变更单、影响分析、验收条件；不可改写已确认资产 |
| 发布门禁 | 输出“可实施 / 缺实现证据 / 口径冲突”三态结论 |

### A3. 数据研发设计 Agent

**定位**：把已确认的产品规则转成可评审的数据工程设计。

| 项目 | 设计 |
|---|---|
| 典型请求 | 建 DWS Index；设计 App 表；补 DDL；设计近 90 天覆盖更新 |
| 输入 | 已确认口径、表资产、数据域模型、调度约束、目标 Doris 版本 |
| 输出 | ODS/DWD/DWS/App 分层设计、粒度与 Key、字段映射、SQL/DDL 骨架、测试 SQL、发布与回滚清单 |
| 核心检查 | 唯一键、分区、分桶、增量边界、覆盖/删除新增方式、维表切片、迟到数据、幂等性 |
| 写权限 | 设计稿、草案 SQL/DDL、测试与发布清单 |
| 发布门禁 | 仅生成建议；代码合并、调度发布和生产写入由人工审批 |

### A4. 数据质量与调度运营 Agent

**定位**：持续确认“今天是否按正确口径产出、回刷是否完成”。

| 项目 | 设计 |
|---|---|
| 典型请求 | 日巡检；月末回刷检查；任务失败分析；数据波动告警；上下游勾稽 |
| 输入 | 已确认核查规则、任务元数据、分区状态、行数/金额/质量统计、告警阈值 |
| 输出 | 巡检报告、异常等级、证据、影响表/报表、建议工单与复验结果 |
| 核心规则 | 只对已确认规则自动告警；区分数据延迟、任务失败、质量异常、口径变更导致的预期波动 |
| 写权限 | 运行记录、异常工单、核查结果；不改生产数据 |
| 初始场景 | V1/V2/经营净利勾稽、31/60/90/120/365 天回刷、月末净利回刷、分区完整性 |

### A5. 数据排查与应用诊断 Agent

**定位**：在报表或应用出现差异时，提供可验证的端到端证据链。

| 项目 | 设计 |
|---|---|
| 典型请求 | 老板报表金额异常；V1/V2 不一致；成本为 0；某店铺数据缺失；回刷未生效 |
| 输入 | 指标/业务单号/日期/筛选条件、资产库、查询结果、DAS/ETL 代码、调度记录 |
| 输出 | 问题范围、逐层数据对比、根因分级、代码与文档锚点、修复建议、复验 SQL |
| 穿透路径 | 应用表 → DWS → DWD → ODS → 维表 → 业务库 → DAS/ETL → 调度 |
| 写权限 | 问答记录、证据链、问题单；不改规则和生产数据 |
| 结论规则 | 明确区分“已证实根因、可能原因、缺少证据”；离线 ETL 未在 DAS 时必须标注边界 |

### A6. 数据产品需求闭环 Agent

**定位**：将需求、禅道、文档版本和上线验收串成可追溯闭环。

| 项目 | 设计 |
|---|---|
| 典型请求 | 生成禅道 PRD；定位需改文档；评审后转开发中；上线后更新最新文档 |
| 输入 | 产品需求、目标版本、A2影响分析、现行产品文档、禅道链接、发布与验收证据 |
| 输出 | PRD、需求变更单、文档修改清单、版本状态、上线验收回写 |
| 状态 | `需求设计 → 开发中 → 已上线` |
| 文档规则 | 仅本期变更标红；历史 Sheet 隐藏保留；已上线版本不可覆盖 |
| 写权限 | Git 中的变更单、PRD 草稿、版本台账；钉钉/禅道需明确授权和连接能力 |

## 4. 统一工作流

| 阶段 | 主责 Agent | 必须产物 | 完成条件 |
|---|---|---|---|
| 需求受理 | A2 | 口径、粒度、影响分析、待确认项 | 业务边界明确 |
| 文档沉淀 | A1 | 版本记录、来源、资产草稿 | 文档与变更可追溯 |
| 技术设计 | A3 | 分层、DDL/SQL 草案、调度与验收 | 开发可评审 |
| 上线验证 | A4 | 核查结果、分区/回刷检查 | 已确认规则验证通过 |
| 异常处置 | A5 | 证据链、修复建议、复验 | 根因或阻塞信息明确 |
| 规则回写 | A1 + A2 | 版本变更与影响记录 | 形成下一轮基线 |
| 需求版本闭环 | A6 | PRD、禅道关联、文档修改单、上线验收回写 | 版本状态为已上线 |

## 5. 权限与安全边界

| 权限等级 | 可执行动作 | 适用 Agent |
|---|---|---|
| L1 只读 | 读取文档、元数据、DDL、代码、查询结果 | 全部 |
| L2 文档写入 | 写草稿、资产、待确认项、核查报告、需求变更单 | A1–A6，按目录授权 |
| L3 开发建议 | 生成 SQL/DDL/调度草案与测试方案 | A3 |
| L4 生产执行 | 发布任务、改生产数据、改权限 | 本期所有 Agent 禁止；必须人工审批与执行 |

生产凭据不应暴露给 Agent；查询应采用最小权限、脱敏与审计记录。成本、供应商、手机号等字段按角色控制明细可见性。

## 6. 共享知识与最小数据模型

| 资产类型 | 必备内容 |
|---|---|
| 表资产 | 表名、层级、粒度、Key、分区、调度、DDL、上下游 |
| 指标资产 | 公式、单位、日期口径、过滤、字段来源、适用版本、确认状态 |
| 血缘资产 | 上游表/字段、转换规则、下游报表与代码锚点 |
| 变更资产 | 需求版本、生效日、差异、影响、审批与回滚 |
| 质量规则 | 检查 SQL、阈值、频率、责任人、告警等级、确认状态 |
| 代码基线 | 仓库、分支、Commit、覆盖范围、未覆盖的 ETL/调度边界 |

## 7. 分阶段上线

### 第一阶段：治理与排查基础（当前）

- 当前对外入口为：**文档版本管理 Agent（A1）**、**数据核对 Agent（A4/A5 的首批结果核对能力）**、**指标口径与影响分析 Agent（A2）**、**数据研发设计 Agent（A3）**、**数据质量与调度运营 Agent（A4）**、**数据排查与应用诊断 Agent（A5）**与**数据产品需求闭环 Agent（A6）**。具体契约见 `agents/document-version-management-agent.md`、`agents/data-reconciliation-agent.md`、`agents/metric-impact-analysis-agent.md`、`agents/data-engineering-design-agent.md`、`agents/data-quality-operations-agent.md`、`agents/data-diagnosis-agent.md` 与 `agents/data-product-requirement-lifecycle-agent.md`。
- 完成销售、售后、库存、采购、净利、老板报表资产的统一登记。
- 以 DAS `das-feature-v5.8.6` 作为当前应用代码对照基线；离线 ETL 单独登记边界。

### 第二阶段：研发与运行闭环

- 上线 A3 的设计、测试和发布清单能力。
- 上线 A4 的分区、回刷、勾稽和异常报告。
- 先覆盖发货 V1、净利 V2、经营净利表及老板报表。

### 第三阶段：平台化扩展

- 接入调度运行日志、ETL 代码仓、权限与数据质量平台。
- 建立指标认证、变更审批、自动影响分析和自动复验。

## 8. 当前首批验收标准

1. 任一指标均能返回：当前版本、公式、来源表字段、刷新规则、确认状态。
2. 任一报表异常均能给出到 DWS/DWD/ODS/维表/代码或 ETL 边界的证据链。
3. 任一变更均能输出受影响表、应用、回刷范围和验收 SQL。
4. 未确认规则不得进入自动告警或正式实现建议。
5. 所有生产动作均保留人工审批门禁。
