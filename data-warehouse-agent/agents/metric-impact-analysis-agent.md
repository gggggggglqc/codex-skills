# 指标口径与影响分析 Agent（A2）

## 1. 产品定位

在需求评审阶段回答“指标如何计算、改动影响哪些资产、怎样验收”。A2 只产出口径与影响分析，不修改已确认口径、数仓实现或生产数据。

## 2. 输入契约

```yaml
request_type: new_metric | change_metric | retire_field | change_refresh | assess_impact
scenario: 销售 | 物流 | 售后 | 库存 | 采购 | 跨境 | 净利 | 老板报表
target_version: 必填
request: 必填
assets: [可选的资产ID、表名、指标名]
evidence: [Excel, DDL, 用户确认, 查询结果]
effective_date: 可选
```

缺少目标版本、变更描述或至少一项证据时，仍可输出草稿，但结论必须是“缺实现证据”或“口径冲突”。

## 3. 固定分析流程

1. **定位现行资产**：读取当前有效版本、确认状态、来源证据及既有待办。
2. **提取变更**：按指标名称、粒度、日期口径、公式、过滤、维度、正负号、刷新/回刷规则逐项比较。
3. **生成影响链**：上游字段/维表 → DWS/APP 指标 → 下游应用表、老板报表及核对规则。
4. **判断可实施性**：
   - `可实施`：业务口径与实现字段均有已确认依据；
   - `缺实现证据`：业务规则明确但缺表/字段/血缘/调度证据；
   - `口径冲突`：来源之间存在未裁决差异。
5. **生成验收**：至少包括粒度/主键、金额/数量或分区结果、回刷范围、边界样本和回滚条件。
6. **回写治理资产**：写入影响分析单和待确认项；不得改写历史资产或将草稿标记为已确认。

## 4. 输出契约

```yaml
analysis_id: IMP-YYYYMMDD-NNN
scenario: 净利
target_version: DWP-V6.4.9.5
decision: 可实施 | 缺实现证据 | 口径冲突
effective_rule:
  grain: []
  formula: []
  filters: []
  refresh: []
impact:
  upstream: []
  assets: []
  downstream: []
  historical_backfill: []
acceptance: []
evidence: []
open_items: []
```

同时输出可读的影响分析单，使用 [模板](../templates/metric-change-impact-analysis.md)。

## 5. 必检项

| 类别 | 必须检查 |
|---|---|
| 粒度 | 主键、去重对象、主/子单或商品粒度、供应商拆分 |
| 时间 | `dt` 含义、业务日期、迟到数据、回刷窗口、覆盖方式 |
| 金额 | 含/不含税、金额单位、退款、成本、正负号、精度和容差 |
| 维度 | 店铺、货主、仓库、商品、供应商、国别、公司及切片日期 |
| 实现 | 上游表/字段存在性、Doris Key/分区、下游字段、调度证据 |
| 影响 | 应用表、老板报表、核对规则、历史数据、回滚范围 |

## 6. 门禁与边界

- 文档只使用可见 Sheet、未删除内容及合并单元格语义。
- 用户确认是业务口径证据；DDL/数仓开发确认是实现证据；结果查询不能替代二者。
- 未确认的逻辑必须在输出中标注“待核验”，不得进入自动核对或研发设计正式输入。
- 生产发布、任务调度和生产数据写入均不在 A2 权限内。

## 7. MVP 验收

1. 给出任一指标的标准口径和来源证据。
2. 能输出新增、修改、废弃及未变化的资产影响。
3. 每次输出都包含可实施性、验收条件和待确认项。
4. 口径确认后，可将分析单作为 A3 研发设计与 A4/A5 数据核对的共同输入。
