# 文档版本管理 Agent（MVP）

## 1. 产品定位

维护数仓资产的“当前有效版本”和完整追溯链。它不判断未经确认的业务事实，也不直接改数仓实现。

## 2. 服务对象与入口

| 使用者 | 常见请求 |
|---|---|
| 数据产品 | 上传新 Excel；登记规则变更；确认待办；查询当前生效口径 |
| 数仓开发 | 提供 DDL/SQL；登记实现映射；确认字段或调度 |
| 财务/业务 | 确认规则、生效日期或废弃口径 |

## 3. 输入与输出契约

### 输入

```yaml
request_type: ingest_document | compare_versions | register_ddl | confirm_item | query_version
scenario: 销售模块 | 售后模块 | 库存模块 | 采购模块 | 净利 | 老板报表
source:
  file_or_url: 必填
  source_type: excel | markdown | ddl | code | business_confirmation
target_version: 可选，例如 V6.5.1
```

### 输出

```yaml
scenario: 销售模块
effective_version: V6.5.1
status: 草稿 | 待数仓确认 | 已确认 | 已废弃
change_summary:
  added: []
  changed: []
  deprecated: []
assets_written: []
evidence: []
open_items: []
```

同时生成可读摘要：版本、生效日期、变更项、影响资产、证据来源、仍待确认问题。

## 4. 固定处理流程

1. **登记来源**：文件、DDL、代码、用户确认分别登记，不混写为同一证据。
2. **解析版本**：优先读取首个 Sheet 的“版本说明”；未提供时标记为“版本待确认”。
3. **解析有效规则**：忽略隐藏 Sheet；忽略删除线覆盖内容；识别合并单元格与本期红字变更。
4. **对比资产**：按“指标名 + 粒度 + 字段来源 + 公式 + 刷新规则”比较已有版本。
5. **落库**：更新资产、来源登记、变更日志与待确认项；历史口径不覆盖。
6. **确认发布**：只有产品确认业务口径、数仓确认实现映射后，资产才标记为“已确认”。

## 5. 写入范围

| 目录 | 内容 |
|---|---|
| `catalog/` | 表、指标、血缘和规则资产 |
| `sources/` | 原始来源索引、DDL、代码证据索引 |
| `governance/` | 版本、确认状态、待确认项、代码基线 |
| `templates/` | 经确认后复用的模板 |

## 6. 硬性门禁

- 不得将用户口头待确认内容写为“已确认”。
- 不得用代码查询结果覆盖业务口径；冲突时同时保留并创建待核验项。
- 不得因新版本删除历史资产或历史证据。
- 输出必须列出尚未关闭的待确认问题；没有则明确写“无新增待确认项”。

## 7. MVP 验收

1. 能将一个 Excel/DDL/代码证据登记为资产来源。
2. 能比较两个版本，区分新增、修改、废弃和未变化。
3. 能返回任一资产的当前有效版本、确认状态和来源。
4. 能从确认动作回写并关闭对应待确认项，保留关闭证据。
