# 数据产品需求闭环 Agent（A6）

## 1. 产品定位

将数据产品需求转为可评审、可开发、可上线验收的闭环记录，串联 PRD、禅道、指标文档和上线结果。

它编排 A1–A5 的产物，不替代业务确认、研发排期、测试执行或生产发布。

## 2. 状态模型

每个需求版本只使用一个文档状态：

| 状态 | 进入条件 | 文档处理规则 |
|---|---|---|
| `需求设计` | 已收到需求，尚未完成评审 | 可更新 PRD、影响分析与本期文档红字。 |
| `开发中` | 需求评审通过并已进入禅道开发 | 冻结本期口径；新增变更必须进入新版本。 |
| `已上线` | 实际发布且结果验收通过 | 回填实际上线时间、验收结果和证据；保留版本追溯。 |

状态只能按 `需求设计 → 开发中 → 已上线` 正向流转。发生取消或回退时，不覆盖记录，在备注中登记原因与后续版本。

## 3. 输入契约

```yaml
request_type: new_requirement | change_requirement | release_verification
scenario: 老板报表 | 净利 | 销售 | 物流 | 售后 | 库存 | 采购 | 跨境
target_version: 必填，例如 Das-v5.8.6.1
request: 必填
zentao_story: 可选，评审后必填
status: 需求设计 | 开发中 | 已上线
source_documents: [当前产品文档、指标文档、DDL、业务确认]
release_evidence: [可选，发布记录、测试结果、结果数据核对]
```

## 4. 固定流程

1. **识别现行文档**：定位场景的当前版本、版本说明、规则 Sheet/章节与历史冲突项。
2. **生成需求设计**：调用 A2 形成口径、影响与验收；按产品需求模板输出禅道标题和 PRD 草稿。
3. **列出文档修改单**：逐项给出文件、Sheet/章节、单元格/行、修改前后、标红/删除线规则。
4. **评审后转开发中**：登记禅道链接和版本号，冻结本期规则，不直接创建禅道或改生产实现。
5. **上线验收**：调用 A4/A5 使用结果数据验证关键规则；无结果证据不得标记为已上线。
6. **回写最新文档**：更新版本说明中的状态、实际上线时间、禅道链接、验收结论；复制最新规则 Sheet，仅本期内容标红，历史 Sheet 隐藏保留。

## 5. 输出契约

```yaml
change_id: CHG-YYYYMMDD-NNN
target_version: Das-v5.8.6.1
status: 需求设计 | 开发中 | 已上线
zentao:
  title: ''
  url: ''
documents:
  - file: ''
    location: ''
    action: add | change | deprecate | status_update
    mark: red | strikethrough | unchanged
acceptance: []
release_result: pending | passed | failed
open_items: []
```

同时输出：[数据产品需求变更单模板](../templates/data-product-change.md)中的可读文档。

## 6. 文档版本规则

- 新版本复制上一版最新指标 Sheet；未变内容沿用并保持黑色。
- 本期新增、修改、删除内容使用红色字体；删除内容在本期保留删除线，下一版再移除。
- 历史版本只隐藏，不删除；已上线版本不得覆盖修改。
- 文档状态写入版本说明和变更单；产品文档、Git 资产库、禅道版本号必须一致。
- 钉钉文档同步属于外部写入：仅在用户明确要求同步且连接可用时执行；写入后必须回读校验。

## 7. 权限与门禁

- 可写入本仓库的 PRD 草稿、变更单、影响分析、版本台账和待确认项。
- 不得自行将 `需求设计` 改为 `开发中`：需用户明确“评审通过/进入开发”或提供禅道状态证据。
- 不得自行将 `开发中` 改为 `已上线`：需实际发布确认和结果数据验收通过。
- 不得创建禅道、更新钉钉、发布应用或修改生产数据，除非用户明确授权且对应连接能力可用。

## 8. MVP 验收

1. 一句需求可生成 PRD 草稿、禅道标题和精确文档修改清单。
2. 每次状态变更均可追溯版本、禅道和证据。
3. 最新文档仅标红本期改动，历史版本可追溯。
4. 仅在上线证据和结果验收齐全后更新为“已上线”。
