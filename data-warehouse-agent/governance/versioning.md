# 版本与确认规则

## 资产版本

- 场景版本使用 `V主版本.次版本.修订号`，应与需求/禅道版本对应。
- 新增兼容字段：增加次版本；口径或字段含义不兼容：增加主版本；文字或来源修订：增加修订号。
- 历史资产不覆盖；使用 Git 提交与资产中的 `valid_from`、`valid_to` 保留追溯链。

## 确认状态

| 状态 | 含义 | 可用于问答 | 可用于自动核查 |
|---|---|---:|---:|
| 草稿 | Agent/产品整理，未确认 | 是，必须提示 | 否 |
| 待数仓确认 | 缺建表/字段/血缘等实现证据 | 是，必须提示 | 否 |
| 已确认 | 产品与数仓开发均确认 | 是 | 是 |
| 已废弃 | 历史保留，不再新用 | 是，仅追溯 | 否 |

## 需求版本文档状态

需求版本使用以下三态，与上表的资产确认状态分开维护：

| 状态 | 含义 | 允许的文档动作 |
|---|---|---|
| 需求设计 | 需求已整理，等待或进行评审 | 可修改本期 PRD、影响分析和当前版本红字内容 |
| 开发中 | 评审通过，已进入禅道开发 | 冻结本期规则；后续口径变化必须新开版本 |
| 已上线 | 已实际发布且结果验收通过 | 回填实际上线时间、验收结果和证据；历史版本只读追溯 |

流转顺序固定为 `需求设计 → 开发中 → 已上线`。状态进入“开发中”需要用户明确评审通过或提供禅道开发证据；进入“已上线”需要实际发布确认和结果数据验收通过。

每个版本说明至少登记：版本号、文档状态、禅道链接、计划上线时间、实际上线时间、维护人和验收结果。新版规则 Sheet 复制上一版最新内容，仅本期新增、修改、删除内容标红；删除内容在本期保留删除线，历史 Sheet 隐藏保留。

## 变更流程

1. 文档管理 Agent 生成资产草稿和差异。
2. 需求整理 Agent 补充影响范围、验收条件和待确认项。
3. 产品确认业务口径；数仓开发确认表结构/SQL 映射。
4. 合并到主分支，并在资产中填入需求版本、生效日期与确认记录。
5. 问题查询与日常核查 Agent 只读取 `已确认` 资产执行自动结论。
