# 团队数仓产品 Agent 包设计

状态：设计待确认
日期：2026-08-21
范围：A1–A6 的团队共享、统一调用与本地文档协作；不包含钉钉、禅道、数据库的自动写入。

## 1. 目标

让产品、研发、测试可从同一仓库调用同一套数仓产品 Agent，输出结构一致、可审阅、可追溯的本地文档；外部系统发布仍由产品明确授权。

## 2. 交付结构

```text
skills/
  data-warehouse-collaboration/     # 统一入口：识别任务并路由 A1–A6
  data-warehouse-document-versioning/ # A1
  data-warehouse-metric-impact/       # A2
  data-warehouse-engineering-design/  # A3
  data-warehouse-quality-operations/  # A4
  data-warehouse-diagnosis/           # A5
  data-product-requirement-lifecycle/  # A6
templates/                             # 复用现有模板
agents/                                # 角色契约与领域参考
governance/                            # 变更单、验收、待确认项、版本记录
docs/team-agent-onboarding.md          # 安装、调用、权限和协作说明
```

每个 Skill 只承担一个角色；统一入口不复制领域规则，只做任务分流并要求读取对应的 Agent 契约与模板。

## 3. 路由规则

| 用户目标 | 路由 | 典型输出 |
| --- | --- | --- |
| 新版本、红字、隐藏历史 Sheet、钉钉文档更新 | A1 | 版本变更清单、文档更新草稿 |
| 指标定义、口径冲突、影响范围 | A2 | 影响分析、验收条件、待确认项 |
| 新建/调整 ODS-DWD-DWS、字段、调度 | A3 | 研发设计、DDL/映射、发布清单 |
| 刷数、回刷、质量异常、调度运行 | A4 | 质量巡检、异常与运行记录 |
| 数据不一致、报表问题、血缘下钻 | A5 | 排查报告、证据链、修复建议 |
| 需求、评审、开发、上线验收闭环 | A6 | PRD、变更单、状态记录、验收结果 |

多目标任务由统一入口按“先 A2 确认口径，再调用相关角色，最后 A6 汇总状态”处理；不并行写同一资产。

## 4. 团队协作与权限

| 角色 | 使用范围 | 外部写入权限 |
| --- | --- | --- |
| 产品 | 全部 Agent；确认口径、状态和发布 | 可在明确指令后授权钉钉、禅道更新 |
| 研发 | A2、A3、A4、A5；阅读 A1、A6 产物 | 默认无外部写入 |
| 测试 | A2、A4、A5、A6；补充验收证据 | 默认无外部写入 |
| 数据负责人 | 全部 Agent；审核口径与数据结论 | 默认无外部写入 |

所有成员可生成本地草稿。任何人都不得绕过 A6 的状态门禁，或在未授权时改写钉钉、禅道、生产任务和生产数据。

## 5. 共享运行方式

1. 团队成员克隆同一 Das 仓库，使用 Git 分支或 PR 审阅文档变更。
2. 成员将 `skills/` 下的团队 Skill 安装或链接到其本机 Codex Skill 目录。
3. 日常从 `$data-warehouse-collaboration` 统一入口调用；熟悉角色后也可直接调用 A1–A6 对应 Skill。
4. 每次产物写入 `governance/` 或已有资产路径，并保留版本、来源证据、确认状态、待确认项。
5. 评审通过、上线验收通过后，产品明确授权同步钉钉或更新禅道。

## 6. 标准调用示例

```text
调用 $data-warehouse-collaboration
场景：老板报表
版本：Das-v5.8.6.1
需求：店铺导出增加平台编码
状态：需求设计
仅生成本地文档，不同步钉钉
```

统一入口应路由至 A6，并在需要时使用 A1 定位文档版本、A2 分析影响。

## 7. 验收标准

1. 团队成员可发现统一入口及 A1–A6 六个 Skill。
2. 统一入口能对六类典型请求给出正确路由和输出位置。
3. 所有 Skill 都引用同一 `agents/` 契约、`templates/` 模板和 `governance/` 记录。
4. 未明确授权时，Skill 只执行本地读写，不调用钉钉、禅道、数据库写操作。
5. 团队说明明确安装方式、调用示例、角色权限和状态流转。

## 8. 非目标

- 本阶段不创建独立侧边栏线程或自动化机器人。
- 本阶段不自动分配禅道任务、不自动发布钉钉、不自动写生产数据。
- 本阶段不替代研发代码评审、测试执行或业务口径确认。
